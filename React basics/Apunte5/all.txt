​Finalmente, tras esta etapa inicial de exploración, el diseño de aviones se asentó ​y se establecieron las normas y las mejores prácticas de construcción de aviones. ​Como el desarrollo de las reglas de construcción de aviones, ​después de los años experimentales de la primera web, ​la comunidad de diseño y desarrollo web se asentó en unos pocos diseños aceptados y esperados. ​Las interfaces de usuario de navegación de los sitios web modernos se centran en la utilidad. ​El famoso libro de Stephen Krug sobre la experiencia del usuario, Don't Make Me Think, ​resume la regla que siguen hoy los desarrolladores. ​Es tu deber como desarrollador y diseñador web seguir las mejores prácticas ​que ya se han establecido. ​Por ejemplo, un volante no pertenece a una lavadora ​o un dial de teléfono antiguo no pertenece a un coche. ​Del mismo modo, no querrá confundir a los visitantes de su sitio web ​dándoles una navegación que puede parecer inteligente, ​pero que es completamente diferente a lo que están acostumbrados. 
​Así que te estarás preguntando, ¿qué es la navegación moderna aceptada en un sitio web ​y cómo funciona en React? ​La navegación web es la parte de cualquier sitio web ​que te permite navegar a través de varias páginas o enlaces en ese sitio web ​desde un único componente. ​Hay varias implementaciones prácticas de este patrón de interfaz de usuario. ​Exploremos brevemente cada una de ellas. ​Los componentes de navegación más comunes son ​una barra de navegación horizontal ​un menú de navegación vertical, ​un menú oculto tras un botón ​y un menú de navegación a pie de página. ​La barra de navegación horizontal suele denominarse barra nav ​y la barra de navegación vertical también se conoce como barra lateral de navegación. ​El menú oculto tras un botón suele representarse mediante un icono ​que tiene tres líneas horizontales ​y se conoce como icono hamburguesa o menú hamburguesa. 
​Una alternativa es el menú de navegación desplegable ​conocido como mega menú. ​Este menú también suele esconderse detrás de un botón ​y suele utilizarse como submenú o menú grande en sitios de comercio electrónico ​y otros sitios que requieren muchos enlaces. ​El menú de navegación a pie de página suele mostrarse ​como varias columnas visuales que contienen enlaces. ​Todos estos patrones de menú mencionados a menudo pueden utilizarse simultáneamente ​en diferentes partes de la misma página. ​Además, una interfaz de navegación más compleja ​puede incluir varios enfoques de navegación en un único componente. ​Por ejemplo, puede tener una barra de navegación horizontal ​o una barra de navegación con elementos de menú desplegables. ​Si utiliza una resolución más pequeña ​la barra de navegación se muestra como un icono de menú hamburguesa. 
​Al hacer clic en el icono del menú hamburguesa ​aparece una barra lateral móvil o un menú vertical. ​Bien, ahora ya estás familiarizado con algunos de los tipos de navegación ​que están disponibles en tus aplicaciones React. ​Exploremos cómo se implementan para cargar diferentes páginas. ​Si comparas la navegación de sitios web ​construidos con React contra HTML y CSS ​es probable que no encuentres ninguna diferencia visual. ​Mientras que visualmente todo parece igual ​en el código React trata la navegación entre páginas de forma diferente. ​Esto se debe a que toda la aplicación se carga dentro de un único div ​por lo que en realidad no estás visitando diferentes páginas ​como lo harías con hipervínculos y archivos HTML. ​En su lugar, el contenido de ese único div es controlado por React ​y se basa en los cambios en el DOM virtual. 
​Actualiza la vista existente o carga una vista completamente nueva ​dando al usuario la impresión de estar visitando una URL completamente diferente. ​Recordemos que con HTML ​los desarrolladores pueden utilizar una lista para crear un menú de navegación. ​Cada elemento de la lista contiene un hipervínculo a un archivo HTML ​y algo de CSS para dar estilo al menú ​como la propiedad display inline para hacer que la lista se muestre horizontalmente. ​Para ayudar a ilustrar cómo funciona la navegación entre páginas con React ​piensa en cómo funcionan los botones del interior de un ascensor. ​Pulsar el botón te llevará a la planta seleccionada. ​Del mismo modo, cada enlace en un sitio web te lleva a una página diferente si haces clic en él. ​Sin embargo, si estás en un ascensor React ​es como si el ascensor nunca se moviera.

En esta lectura, aprenderás sobre las diferencias entre las páginas web tradicionales y las páginas web potenciadas por React (SPAs - single page applications).

Una vez que entiendas la diferencia entre estas dos formas de construir páginas web, podrás comprender la necesaria diferencia entre cómo funciona la navegación en las aplicaciones web tradicionales frente a cómo funciona en las modernas páginas web SPA.

Antes de las Single-Page Apps
Antes de la llegada de los modernos frameworks JavaScript, la mayoría de los sitios web se implementaban como aplicaciones multipágina. Es decir, cuando un usuario hace clic en un enlace, el navegador navega a una nueva página web, envía una petición al servidor web; éste responde con la página web completa y la nueva página se muestra en el navegador.

Esto puede hacer que su aplicación consuma muchos recursos del servidor web. El tiempo de CPU se gasta renderizando páginas dinámicas y el ancho de banda de la red se utiliza enviando páginas web enteras de vuelta para cada petición. Si su sitio web es complejo, puede parecer lento a sus usuarios, incluso más si tienen una conexión a Internet lenta o limitada.

Para resolver este problema, muchos desarrolladores desarrollan sus aplicaciones web como Single Page Applications.

Aplicaciones de Página Única
Utilizas muchas Single Page Applications cada día. Piensa en tu red social favorita, o en tu proveedor de correo electrónico online, o en la aplicación de mapas que utilizas para encontrar negocios locales. Sus excelentes experiencias de usuario están impulsadas por las Aplicaciones de Página Única.

Una aplicación de página única permite al usuario interactuar con el sitio web sin necesidad de descargar nuevas páginas enteras. En su lugar, reescribe la página web actual a medida que el usuario interactúa con ella. El resultado es que la aplicación será más rápida y responderá mejor al usuario.

¿Cómo funciona una aplicación de una sola página?
Cuando el usuario navega a la aplicación web en el navegador, el Servidor Web devolverá los recursos necesarios para ejecutar la aplicación. Hay dos enfoques para servir código y recursos en las Aplicaciones de Página Única.

Cuando el navegador solicita la aplicación, devuelve y carga todo el HTML, CSS y JavaScript necesario inmediatamente. Esto se conoce como bundling.

Cuando el navegador solicita la aplicación, devolver sólo el mínimo HTML, CSS y JavaScript necesarios para cargar la aplicación. Los recursos adicionales se descargan cuando la aplicación lo requiere, por ejemplo, cuando un usuario navega a una sección específica de la aplicación. Es lo que se conoce como lazy loading o code splitting.

Ambos enfoques son válidos y se utilizan en función del tamaño, la complejidad y los requisitos de ancho de banda de la aplicación. Si tu aplicación es compleja y tiene muchos recursos, tus paquetes crecerán bastante y tardarán mucho tiempo en descargarse, ¡posiblemente acaben siendo más lentos que una aplicación web tradicional!

Una vez cargada la aplicación, toda la lógica y los cambios se aplican a la página web actual.

Ejemplo de aplicación de una sola página
Imagina que hay una página web que tiene una etiqueta y un botón. Mostrará un nombre de película aleatorio cuando se haga clic en el botón.

En una página web tradicional, cuando se pulsa el botón, el navegador envía una petición GET al servidor web. El servidor web devolverá una nueva página web que contiene el botón y el nombre de la película, y el navegador web renderiza la nueva página.

En una Aplicación de Página Única, cuando se pulsa el botón, el navegador envía una petición GET al servidor web. El servidor web devolverá un objeto JSON. La aplicación lee el objeto y actualiza la etiqueta con el nombre de la película.

Ves, ¡más eficiente!

Pero, ¿qué pasa si necesitamos tener varias páginas con diferentes diseños en nuestra aplicación?

Diagrama de aplicación de página única con varias plantillas cargadas en una sola página
Aplicación de página tradicional con varias páginas para cargar
Tienes una aplicación web que tiene una barra de navegación en la parte superior y dos páginas. Una página muestra las últimas noticias, y la otra muestra la página de perfil del usuario actual. La barra de navegación contiene un enlace para cada página.

En un sitio web tradicional, cuando el usuario hace clic en el enlace Perfil, el navegador web envía la solicitud al servidor web. El servidor genera la página HTML y la devuelve al navegador. A continuación, el navegador renderiza la nueva página web.

En una aplicación de una sola página, las diferentes páginas se dividen en plantillas (o vistas). Cada vista tendrá código HTML que contiene variables que pueden ser actualizadas por la aplicación.

El navegador envía la petición al servidor web, y éste devuelve un objeto JSON. El navegador entonces actualiza la página web insertando la plantilla con las variables reemplazadas por los valores en el objeto JSON.

Elementos de etiqueta de anclaje en elementos de una sola página
Una aplicación de una sola página no puede tener elementos de etiqueta de anclaje normales como una aplicación web tradicional. 

La razón es que el comportamiento predeterminado de una etiqueta de anclaje es cargar otro archivo HTML desde un servidor y actualizar la página. Esta actualización de la página no es posible en una SPA que funciona con una librería como React, porque una actualización total de la página no es la forma en que funciona una SPA, como se explicó anteriormente en esta lección. 

En su lugar, una SPA viene con su propia implementación especial de etiquetas de anclaje y enlaces, que sólo dan la ilusión de cargar diferentes páginas para el usuario final, cuando en realidad, simplemente cargan diferentes componentes en un único elemento del DOM real en el que se monta y actualiza el árbol DOM virtual.

Por eso la navegación en una aplicación de una sola página es fundamentalmente diferente de su contrapartida en una aplicación multipágina. Comprender los conceptos esbozados en esta lección te convertirá en un desarrollador React más completo.

​Tenga en cuenta también que las etiquetas nav ​están fuera de la etiqueta de rutas, ​lo que significa que la navegación está fuera de las rutas. ​Finalmente, necesito reemplazar las ​etiquetas de anclaje con vínculos de enrutador React. ​Esto permite que el componente correcto ​se cargue al hacer clic en el enlace, ​en lugar de simplemente actualizar la página. ​En el componente de la aplicación, ​la etiqueta de anclaje para la página de inicio se ​vincula a igual y ​y luego la barra diagonal entre comillas dobles. ​A continuación se coloca class name igual a, y ​y luego nav-item entre comillas dobles. ​Para Aboutme, el cambio es similar, salvo que ​about-me aparece después de la barra oblicua. ​También necesito importar el enlace desde ​react-router-dom y guardar mis cambios.

La representación condicional se basa en el mismo principio. Usando condiciones, un componente puede devolver diferentes componentes hijos. Esto se hace a menudo utilizando los props pasados a ese componente, pero también puede hacerse basándose en el propio estado del componente.

function LogInOutButton(props) {

  } else {
    return <LoginButton />;

Es probable que los archivos de la aplicación se agrupen cuando se trabaja con una aplicación React. La agrupación es un proceso que toma todos los archivos importados de una aplicación y los une en un único archivo, denominado paquete. Varias herramientas pueden realizar esta agrupación. Dado que, en este curso, has utilizado create-react-app para construir varias aplicaciones React, te centrarás en webpack. Esto se debe a que webpack es la herramienta integrada en create-react-app.

Empecemos explicando qué es webpack y por qué lo necesitas.

En pocas palabras, webpack es un agrupador de módulos.

En la práctica, esto significa que tomará varios tipos de archivos, como archivos SVG y de imagen, archivos CSS y SCSS, archivos JavaScript y archivos TypeScript, y los empaquetará juntos para que un navegador pueda entender ese paquete y trabajar con él.

¿Por qué es importante?

Al crear sitios web, probablemente podrías prescindir de webpack, ya que la estructura de tu proyecto puede ser sencilla: puede que tengas una única biblioteca CSS, como Bootstrap, cargada desde una CDN (red de distribución de contenidos). También puede tener un único archivo JavaScript en su documento HTML estático. Si eso es todo, no es necesario utilizar webpack en tal escenario.

Las importaciones aquí son de bibliotecas y recursos ficticios porque las bibliotecas específicas no son necesarias. Todas estas importaciones diferentes pueden ser de varios tipos de archivos: .js, .svg, .css, y así sucesivamente.

A su vez, todos los archivos importados pueden tener sus propios archivos importados, e incluso éstos pueden tener sus importaciones.

Esto significa que, dependiendo de otros archivos, todos estos archivos pueden crear un gráfico de dependencias. El orden en el que se cargan todos estos archivos es esencial. Ese gráfico de dependencias puede llegar a ser tan complejo que se hace casi imposible para un humano estructurar un proyecto complejo y agrupar todas esas dependencias correctamente.

Esta es la razón por la que necesitas herramientas como webpack.

Así, webpack construye un gráfico de dependencias y agrupa los módulos en uno o más archivos que un navegador puede consumir.

Puede trabajar con herramientas como Babel para convertir JavaScript moderno en una sintaxis JavaScript más antigua que pueda entender una gama más amplia de navegadores. Este proceso se conoce como transpiling. Por ejemplo, en un proyecto basado en webpack, Babel puede transpilar la sintaxis JavaScript más reciente a una versión más antigua que sea compatible con más navegadores.

Puede crear mapas de código fuente, que le ayudarán a depurar el código empaquetado asignando el código que se ejecuta en el navegador a los archivos fuente originales que usted escribió.

Puede producir varios tipos de archivos basados en reglas y plantillas. Esto incluye archivos HTML, entre otros.

Otra característica significativa de webpack es que ayuda a los desarrolladores a crear aplicaciones web modernas.

Te ayuda a lograrlo usando dos modos: modo de producción o modo de desarrollo .

En el modo de desarrollo, webpack agrupa tus archivos y optimiza tus paquetes para las actualizaciones, de modo que cualquier actualización de cualquiera de los archivos de tu aplicación desarrollada localmente se vuelve a agrupar rápidamente. También construye mapas de fuentes para que puedas inspeccionar los archivos fuente originales detrás del código empaquetado, lo que hace que la depuración sea mucho más fácil durante el desarrollo.

En el modo de producción, webpack agrupa los archivos para que estén optimizados para la velocidad. Esto significa que los archivos son minificados y organizados para ocupar la menor cantidad de memoria. Por lo tanto, están optimizados para la velocidad porque estos paquetes se descargan rápidamente cuando un usuario visita el sitio web en línea.

Una vez que todos los archivos fuente de tu aplicación se han agrupado en un único archivo bundle, éste se sirve a un visitante que navega por la versión en línea de tu aplicación, y todo el contenido de la aplicación se sirve a la vez.

Esto funciona muy bien para las aplicaciones más pequeñas, pero si tienes una aplicación más extensa, es probable que este enfoque afecte a la velocidad de tu sitio. Cuanto más tarde en cargarse una aplicación web, más probable es que el visitante la abandone y se dirija a otro sitio web no relacionado. Hay varias formas de abordar este problema de los paquetes grandes.

Uno de estos enfoques es la división de código, una práctica en la que un agrupador de módulos como webpack divide el archivo de paquete único en varios paquetes, que luego se cargan según sea necesario. Con la ayuda de la división del código, puedes cargar sólo las partes que el visitante de la aplicación necesita en un momento dado. Este enfoque reduce significativamente los tiempos de descarga y permite que las aplicaciones basadas en React obtengan velocidades mucho mejores.

Hay otras formas de abordar estos problemas.

Un ejemplo de alternativa viable es SSR (Server-side rendering).

Con SSR, los componentes de React se convierten en HTML en el servidor, y el visitante descarga el código HTML terminado. Una alternativa a SSR es la renderización del lado del cliente, que descarga el archivo index.html y luego deja que React inyecte su propio código en un elemento HTML dedicado (el elemento raíz en create-react-app). En este curso, sólo has trabajado con renderizado del lado del cliente.

A veces, puedes combinar renderizado del lado del cliente y renderizado del lado del servidor. Este enfoque resulta en lo que se conoce como aplicaciones isomórficas.
