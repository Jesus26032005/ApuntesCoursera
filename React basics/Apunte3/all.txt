Errores de eventos
Cuando trabajas en cualquier entorno de programación, lenguaje o framework, estás obligado a escribir código que lanza errores, por una variedad de razones.

A veces se trata simplemente de escribir la sintaxis incorrecta. Otras veces se trata de no pensar en todos los escenarios posibles y todas las formas posibles en que las cosas pueden ir mal en tu código.

Independientemente de la causa, los errores forman parte del día a día de un desarrollador.

El lenguaje JavaScript viene con una sintaxis de manejo de errores incorporada, la sintaxis try...catch.

Examinemos un ejemplo de error en JavaScript:

1
(5).toUpperCase()
Obviamente, no se puede poner en mayúsculas un valor numérico, y por lo tanto, esto arroja el siguiente error:

1
Uncaught TypeError: 5.toUpperCase is not a function
Para manejar este TypeError, puede actualizar el código con un bloque try...catch que ordene al código continuar ejecutándose después de encontrar el error:

1234567
try {
    (5).toUpperCase();
} 
catch(e) {
    console.log(`Oops, you can't uppercase a number. 
        Trying to do it resulted in the following`, e);
}
El bloque try-catch mostrará algún texto en la consola:

Oops, no puedes poner un número en mayúsculas. Al intentar hacerlo se produce el siguiente TypeError: 5.toUpperCase no es una función

En React, normalmente usarías try...catch dentro de código que se ejecuta en respuesta a un evento, como un manejador de clic, si quieres manejar un error sin detener el resto de tu código.

En esta lectura, aprenderás las diferentes formas de incrustar expresiones en manejadores de eventos en React:

Con una función ES5 anónima en línea

Con una función ES6 anónima en línea (una función de flecha)

Usando una declaración de función separada

Usando una expresión de función separada

Puede que esta lectura te resulte útil como hoja de referencia.

Para mayor claridad y simplicidad, una función simplemente registrará en la consola algunas palabras. Esto le permitirá comparar la diferencia en la sintaxis entre estos cuatro enfoques, mientras que el resultado de la gestión de eventos siempre será el mismo: sólo algunas palabras de salida a la consola.

Manejo de eventos usando funciones ES5 anónimas en línea
Este enfoque le permite pasar directamente una declaración de función ES5 como valor del atributo event-handling de onClick:

123
<button onClick={function() {console.log('first example')}}>
    An inline anonymous ES5 function event handler
</button>
Aunque es posible escribir tus manejadores de clic usando esta sintaxis, no es un enfoque común y no encontrarás este tipo de código muy a menudo en aplicaciones React.

Manejo de eventos usando funciones ES6 anónimas en línea (funciones flecha)
Con este enfoque, puedes pasar directamente una declaración de función ES6 como valor del atributo de manejo de eventos onClick:

123
<button onClick={() => console.log('second example')}>
    An inline anonymous ES6 function event handler
</button>
Este enfoque es mucho más común que el anterior. Si desea mantener toda su lógica dentro de la expresión JSX asignada al atributo onClick, utilice esta sintaxis.

Manejo de eventos usando declaraciones de funciones separadas
Con este enfoque, declaras una función ES5 separada, y luego haces referencia a su nombre en el atributo event-handling onClick, como se muestra a continuación:

12345678910111213
function App() {
    function thirdExample() {
        console.log('third example');
    };
    return (
        <div className="thirdExample">
            <button onClick={thirdExample}>
                using a separate function declaration
            </button>
        </div>

Esta sintaxis tiene sentido cuando la lógica onClick es demasiado compleja para caber fácilmente en una función anónima. Aunque este ejemplo no muestra realmente este escenario, imagina una función que tiene, por ejemplo, 20 líneas de código, y que necesita ejecutarse cuando se dispara el evento click. Este es un caso de uso perfecto para una declaración de función separada.

Gestión de eventos mediante expresiones de función independientes
Consejo: Una forma de determinar si una función está definida como una expresión o una declaración es: si no comienza la línea con la palabra clave function, entonces es una expresión.

En el siguiente ejemplo, está asignando una función de flecha ES6 anónima a una variable const - por lo tanto, se trata de una expresión de función.

Luego está usando el nombre de esta variable const para manejar el evento onClick, por lo que este es un ejemplo de manejo de eventos usando una expresión de función separada.

123456789101112
function App() {
    const fourthExample = () => console.log('fourth example');

    return (
        <div className="fourthExample">
            <button onClick={fourthExample}>
                using a separate function expression
            </button>
        </div>
  );

La sintaxis de este ejemplo es muy común en React. Utiliza funciones de flecha, pero también nos permite manejar situaciones en las que nuestra expresión de función separada abarca varias líneas de código.

Flujo de datos padre-hijo
En React, el flujo de datos es unidireccional. A veces se dice que el flujo de datos es unidireccional. Dicho de otra manera, los datos en React fluyen de un componente padre a un componente hijo. El flujo de datos comienza en la raíz y puede fluir a múltiples niveles de anidamiento, desde el componente raíz (componente padre) al componente hijo, luego al componente nieto, y más abajo en la jerarquía.

Una aplicación React consta de muchos componentes, organizados como un árbol de componentes. Los datos fluyen desde el componente raíz a todos los componentes en la estructura de árbol que requieren estos datos, utilizando props.

Las props son inmutables (no se pueden cambiar).

Los dos principales beneficios de este flujo de datos unidireccional son que permite a los desarrolladores:

comprender la lógica de las aplicaciones React más rápidamente y

simplificar el flujo de datos.

He aquí un ejemplo práctico de esto:

Imagina que el componente padre pasa varios props al componente hijo, como name, bowlShape, y bowlStatus. El componente hijo puede utilizar algunos de estos props directamente y pasar otros a su propio componente hijo.

En este ejemplo, Dog pasa props a Puppy, y Puppy pasa algunos de esos mismos props a Bowl, lo que demuestra cómo los datos pueden moverse de un padre a un hijo y luego a un nieto.

Hacer que los datos se muevan a través de los accesorios en una sola dirección hace que sea más sencillo entender la lógica de cómo interactúan los componentes. Si los datos se movieran por todas partes, todo el tiempo, entonces sería mucho más difícil comprender su flujo lógico. Cualquier optimización que intentaras implementar probablemente no sería tan eficiente como podría ser, especialmente en React moderno.
